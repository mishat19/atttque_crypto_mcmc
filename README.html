BUT 3 — projet de cryptographie

Attaques cryptographiques : moteur MCMC et interface web

Ce dépôt contient deux systèmes distincts qui étudient les chiffrements classiques en français : un moteur terminal fondé sur une chaîne de Markov Monte Carlo (MCMC), et une interface graphique locale dans le navigateur. Les deux partagent la bibliothèque de chiffrements, mais ne communiquent pas entre eux à l'exécution.

1. Architecture 2. Système terminal 3. Système graphique 4. Lien entre les deux 5. Comparaison 6. Démarrage 7. Fichiers 8. Théorie

01 / VUE D'ENSEMBLEArchitecture générale

L'application n'est pas un seul programme avec deux modes d'affichage : ce sont deux points d'entrée indépendants (mcmc/main.py et utils/app.py) posés sur une couche commune de modules de chiffrement.

[ TERMINAL ] [ NAVIGATEUR ] mcmc/main.py (CLI + moteur MCMC) utils/app.py (serveur HTTP + HTML/JS intégré) │ │ ├── mcmc/utils/{score,mutation, ├── analyse Markov d'un article Wikipédia │ selection,initialisation,substitution} │ (matrix 27x27, fréquences, digrammes) │ │ └──────────────┐ ┌────────┘ ▼ ▼ COUCHE PARTAGÉE chiffrements/ permutation/ substitution/ (César, Vigenère, attaque fréquentielle, permutation par blocs) │ │ └────────┬───────────┘ ▼ mcmc/dictionnaire_fr.txt (utilisé par le WEB uniquement) mcmc/reference.txt (utilisé par le TERMINAL uniquement)
Point clé à retenir Les deux systèmes se partagent le code source (les imports Python), pas un état d'exécution. Il n'y a ni socket entre eux, ni fichier de session commun écrit par l'un et lu par l'autre, ni API appelée par le CLI vers le serveur web.

Deux objectifs différents

Terminal / MCMC

Retrouver une clé inconnue

On part d'un cryptogramme dont on ignore la clé. On échantillonne l'espace des clés avec une chaîne MCMC et on affiche les meilleures propositions. L'être humain lit les textes et choisit le bon.

  • Substitution des 26 lettres (26! clés)
  • Permutation de positions de longueur ℓ (ℓ! clés)
  • Score de crédibilité basé sur les bigrammes de reference.txt
Navigateur / interface web

Explorer et comprendre les chiffres

On analyse un texte, on visualise la matrice de Markov, puis on chiffre, déchiffre avec une clé connue et attaque avec la méthode fréquentielle classique. L'accent est mis sur la pédagogie et la visualisation.

  • Analyse Wikipédia ou fichier .txt local
  • 3 cartes : César, Vigenère, Permutation
  • Attaque fréquentielle par colonnes + surlignage des mots inconnus

02 / SYSTÈME TERMINALLe moteur MCMC

Tout se joue dans mcmc/main.py : un seul moteur, deux "facettes" (lettres ou positions) fournies par injection des fonctions dechiffrer, muter et formater.

Les deux modes

Mode Espace des clés Mutation proposée Fichier chiffré
--mode lettres
partie 1.3 du sujet 		Permutation des 26 lettres
26! ≈ 4·1026 clés 		Échange de deux lettres au hasard (muter_lettres) mcmc/chiffre.txt
--mode positions
partie 1.4 du sujet 		Permutation de 0..ℓ-1
ℓ! clés, ℓ testé de 2 à 8 		Déplacement d'un sous-bloc (i, L, d) (muter_positions) mcmc/chiffre_positions.txt

Déroulé d'une attaque

  1. Apprendre la langue : lire_texte(reference.txt) normalise le corpus (accents retirés, espace conservé comme 27e symbole), puis construire_log_r compte les bigrammes et stocke log(1 + nb_occurrence).
  2. Choisir un départ : cle_aleatoire() ou cle_heuristique() (la lettre chiffrée la plus fréquente est associée à E, etc.).
  3. Lancer la chaîne : marche_mcmc() propose une mutation, calcule log S avec un cache, applique la règle de Markov (accepter_log), puis comptabilise les visites après la période de chauffe.
  4. Agréger : fusionner_etats / fusionner_candidats regroupent les redémarrages ; fusionner_vue réunit visites et propositions.
  5. Classer et afficher : classer garde les n meilleures clés (par score ou par visites) et afficher_propositions montre les 100 premiers caractères déchiffrés. C'est à l'utilisateur de juger quel texte est lisible.

Commandes

# 1) Fabriquer un cryptogramme de test (on connaît la clé)
python3 mcmc/chiffrer.py --mode lettres --graine 1
python3 mcmc/chiffrer.py --mode positions --longueur-cle 4 --longueur 3000 --graine 1

# 2) Attaquer le cryptogramme
python3 mcmc/main.py --mode lettres
python3 mcmc/main.py --mode positions --longueur-max 8 --redemarrages 3

# 3) Vérifier les briques unitaires
python3 mcmc/tests/test_mcmc.py

Options principales de mcmc/main.py

Option Défaut Rôle
--iterations 20 000 Nombre de propositions de clés par chaîne
--chauffe 0.10 Fraction des itérations ignorée avant de comptabiliser les visites
--propositions 5 Nombre de candidats affichés
--initialisation heuristique heuristique (fréquences) ou aleatoire
--longueur-min/max 2 / 8 Intervalle de ℓ exploré en mode positions
--redemarrages 1 Nombre de chaînes indépendantes fusionnées par longueur
--classement score score (log S) ou visites (temps passé)
--graine — Rend l'attaque reproductible
--reference, --chiffre fichiers de mcmc/ Permet de changer de corpus ou de cryptogramme
Lecture du résumé "positions" Le tableau final affiche log S − log(ℓ!) : c'est une pénalité de complexité. Un ℓ plus grand explore plus de clés et peut coller aux bigrammes par hasard. On choisit ensuite la plus petite longueur ℓ dont le texte est lisible, pas forcément celle au score brut le plus élevé.

Les utilitaires du moteur

Fichier Responsabilité

mcmc/utils/mutation.py Échange de lettres, déplacement de bloc (propositions symétriques)
mcmc/utils/selection.py Règle d'acceptation de Markov en logarithmique

03 / SYSTÈME GRAPHIQUEL'interface web locale

Tout tient dans utils/app.py (environ 1 300 lignes) : un serveur Python standard, une page HTML/CSS/JavaScript intégrée dans une chaîne PAGE, et zéro dépendance externe.

Comment ça démarre

python utils/app.py
# Interface disponible sur http://127.0.0.1:8765/  (Ctrl+C pour arrêter)

main() crée un ThreadingHTTPServer lié à 127.0.0.1:8765, planifie un webbrowser.open après 0,6 s, puis serve_forever(). Le serveur n'écoute que la machine locale : aucun risque d'exposition réseau.

Le cycle d'une requête

  1. Le navigateur charge / : le serveur renvoie directement la chaîne PAGE (HTML + CSS + JS embarqués).
  2. L'utilisateur choisit un article Wikipédia (ou un .txt) et clique sur Analyser. Le JS appelle /api/analyse (GET) ou /api/analyse-texte (POST).
  3. Le serveur filtre le texte sur 27 symboles, calcule les fréquences, les digrammes et la matrice de Markov, puis les stocke dans ETAT et renvoie le tout en JSON.
  4. Le JS dessine la matrice (27×27 cases colorées), les histogrammes et génère un texte aléatoire via /api/generer.
  5. Dans chaque carte, l'utilisateur suit l'ordre 1 Cryptogramme → 2 Décrypter → 3 Attaque. Les boutons 2 et 3 restent désactivés tant que l'étape 1 n'a pas produit de cryptogramme.

Les trois cartes de chiffrement

Carte Clé Chiffrement Attaque proposée
César Un entier 0–25 Décalage fixe de toutes les lettres Corrélation des fréquences avec le français, 26 scores classés
Vigenère Un mot (ex. ORACLE) Un décalage par lettre, clé répétée ; la clé avance sur les lettres uniquement Découpage en L colonnes (une César par colonne), score par décalage
Permutation Un mot (ex. LEMON) Vigenère positionnel (espaces compris) puis permutation par blocs Mêmes décalages par colonne + recherche de l'ordre des colonnes par score de bigrammes (L! essais, si le texte ≥ 200 caractères)

Les routes HTTP

Méthode Route Action
GET / Sert la page complète
GET /api/analyse Télécharge et analyse un article Wikipédia
POST /api/analyse-texte Analyse le contenu d'un fichier .txt importé
GET /api/generer Génère un texte selon la matrice courante
GET /api/cesar Chiffre ou déchiffre avec un décalage
GET /api/vigenere Chiffre ou déchiffre avec un mot-clé
GET /api/permutation Chiffre ou déchiffre avec Vigenère + permutation
GET /api/attaque Attaque fréquentielle de César
GET /api/attaque-vigenere Attaque par colonnes de Vigenère
GET /api/attaque-permutation Attaque par colonnes de la permutation

Toute exception côté serveur est convertie par Handler._sur() en {"erreur": "..."} et affichée en rouge dans la barre d'état : le serveur ne plante donc pas sur une mauvaise saisie.

Astuce interface Les étoiles (★) marquent le décalage jugé le plus probable pour chaque colonne. Cliquer sur une autre ligne du classement garde les meilleurs décalages ailleurs et remplace uniquement la colonne choisie : on peut ainsi réparer une erreur de l'attaque fréquentielle à la main. Les mots absents du dictionnaire sont surlignés en jaune dans l'onglet "Déchiffre".

Et utils/stats.py ?

C'est l'ancêtre terminal de l'analyse Markov : mêmes calculs (fréquences, digrammes, matrice, génération) mais affichage ASCII dans le terminal, article Wikipédia codé en dur (Paris) et dépendance externe requests. Le bloc de démonstration s'exécute dès le lancement. L'interface web en est la version aboutie : urllib à la place de requests, article configurable et visualisation.

  • clair.txt : texte source utilisé par le générateur de cryptogrammes du terminal.

06 / DÉMARRAGEInstallation et commandes

Prérequis

  • Python 3.10 minimum (annotations int | None, tuple[int, ...] utilisées dans le code).
  • Aucune dépendance pour utils/app.py et pour le MCMC : uniquement la bibliothèque standard.
  • Seul utils/stats.py nécessite requests : pip install requests.
  • Connexion Internet pour analyser un article Wikipédia (inutile pour un .txt local).
  • Les fichiers texte de mcmc/ doivent rester en place (reference.txt ~478 Ko, dictionnaire_fr.txt ~3,6 Mo).

Depuis la racine du dépôt

# Interface graphique
python utils/app.py

# Attaque MCMC — substitution de lettres
python3 mcmc/main.py --mode lettres --graine 1

# Attaque MCMC — permutation de positions
python3 mcmc/main.py --mode positions --longueur-max 8

# Génération d'un cryptogramme de test, puis attaque
python3 mcmc/chiffrer.py --mode lettres --graine 1
python3 mcmc/main.py --mode lettres --initialisation aleatoire

# Tests unitaires
python3 mcmc/tests/test_mcmc.py

# Auto-démonstration de la permutation du sujet (BONJOUR -> OJNBURO)
python permutation/bloc.py

# Ancienne démo terminal de la chaîne de Markov (nécessite requests)
python utils/stats.py
Si un fichier est introuvable Le CLI affiche un message invitant à lancer mcmc/chiffrer.py pour créer chiffre.txt ou chiffre_positions.txt. Les chemins par défaut sont toujours relatifs au dossier du script, pas au répertoire courant.

08 / RAPPELS THÉORIQUESPourquoi ça marche

Le score de crédibilité

Le moteur terminal maximise :

S(k) = ∏(x,y) r(x,y)1 + fk(x,y)

r(x,y) = 1 + nombre de bigrammes xy dans reference.txt
fk(x,y) = nombre de bigrammes xy dans le texte déchiffré par k

log S(k) = Σ (1 + fk(x,y)) · log r(x,y)

Avec un a priori uniforme sur les clés, la loi a posteriori est proportionnelle à S(k) : les clés produisant un texte proche du français sont les plus crédibles. Le passage au logarithme évite les produits gigantesques.

La règle de Markov

On accepte toujours une clé de score supérieur ; une clé moins bonne est acceptée avec probabilité : 

P(accepter k → k') = min(1, S(k') / S(k))
                   ⇔ log U < log S(k') − log S(k),  U ~ Uniforme(0,1)

Les mutations sont symétriques : échanger i et j est réversible, et (i, L, d) est annulé par (d, L, i). La chaîne est irréductible (toutes les clés sont atteignables) et apériodique (un refus ou un déplacement i == d permet de rester sur place). Elle converge donc vers π(k) ∝ S(k) : les bonnes clés sont visitées le plus souvent, d'où l'intérêt du critère --classement visites.

Pourquoi l'attaque fréquentielle suffit dans le navigateur

Pour César, il n'existe que 26 clés : on les teste toutes. Pour Vigenère, chaque colonne est un César indépendant : L×26 tests suffisent. Pour la permutation combinée, les décalages sont retrouvés de la même manière, mais il reste L! ordres possibles : c'est là que le score de bigrammes et, côté terminal, le MCMC prennent le relais.

Limites connues

  • La chaîne de Markov du navigateur n'est pas irréductible sur ses 27 états : certains symboles n'ont aucune transition sortante. La loi stationnaire ne porte que sur la classe récurrente (voir la note dans utils/stats.py).
  • L'attaque fréquentielle par colonnes devient incertaine sur un texte trop court : c'est pourquoi le réordonnancement par bigrammes de l'interface web exige au moins 200 caractères.
  • Le serveur web garde un seul document actif dans ETAT : ouvrir plusieurs onglets analysant des textes différents se écraserait mutuellement.
  • Le score MCMC dépend fortement de la qualité et de la longueur du corpus de référence : reference.txt est fourni à cet effet.
